# Security

## Supported versions

While RYVR is in beta, only the latest release on `main` is supported. Earlier
releases do not receive security fixes.

## Report a vulnerability

Use **Report a vulnerability** on the repository's **Security** tab to open a
[private security advisory](https://github.com/RyvrAnalytics/ryvr/security/advisories/new).
Never report a vulnerability in a public issue, pull request or discussion.

Include:

- The affected version or commit and component.
- Steps to reproduce, with a small proof of concept if possible.
- The impact and any permissions or configuration needed to reproduce it.
- Relevant logs or screenshots, with secrets and personal data removed.
- A suggested fix, if you have one.

## What to expect

Maintainers aim to acknowledge reports within 3 business days. Updates are on a
best effort basis while the report is investigated and a fix is prepared.

We coordinate disclosure with the reporter so a fix can be released before details
become public. Please keep the report private until an agreed disclosure date. We
give credit on request.

## Scope

The RYVR app, the tracker (`r.js`) and the embed library are in scope.

Out of scope:

- Denial of service by volume.
- Social engineering.
- Findings that require a compromised server.

## Safe harbour

We consider good-faith research that follows this policy authorized and will not
pursue legal action against researchers for that work. Test only systems you own
or have permission to test. Avoid disrupting service, accessing other people's
data or changing data without permission. Stop and report privately if you
encounter personal data or secrets.

This policy covers the maintainers' actions and cannot grant permission on behalf
of other system owners or bind third parties.
